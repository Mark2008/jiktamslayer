# 직업탐구 문제 생성기 — `jiktamslaeyr`

## 1. 프로젝트 개요

**목표:** 「성공적인 직업 생활」 교과서와 기출문제를 분석하여, 출제 가능한 연습문제를 자동 생성하고 문서로 출력하는 도구를 만든다.

- **주 사용자:** 직업탐구 영역을 공부하는 수험생
- **핵심 기능:** 교재 분석 → 개념 구조화 → 문제 생성 → 검수 → 문서 출력
- **개발 언어:** Python
- **개발 시기:** 수능 이후
- **개발 원칙:** 처음부터 완전 자동화를 추구하지 않고, 사람이 검수할 수 있는 작은 시스템부터 만든다.

## 2. 해결하려는 문제

- 기존 문제만으로는 충분한 연습량을 확보하기 어려울 수 있다.
- 교재의 개념을 변형하여 새로운 문제를 만드는 데 시간이 든다.
- AI가 생성한 문제는 정답 오류, 교육과정 이탈, 기출문제와의 중복 등이 발생할 수 있다.
- 생성한 문제를 실제로 풀 수 있는 문서 형태로 편집하는 작업도 번거롭다.

## 3. 전체 파이프라인

```text
교재 PDF 및 기출문제
        ↓
[1] 문서 파싱
        ↓
[2] 개념·표·그림 구조화
        ↓
[3] 출제 요소 분석
        ↓
[4] 문제 및 선지 생성
        ↓
[5] 자동 검증 및 사람의 검수
        ↓
[6] 시험지·정답·해설 출력
```

## 4. 단계별 개발 계획

### Phase 0. 자료 조사 및 기준 설정

- [ ] 사용할 교재와 기출문제 확보
- [ ] 자료의 저작권 및 이용 범위 확인
- [ ] 문제 유형과 출제 요소 분류 기준 정의
- [ ] 생성 문제의 품질 평가 기준 마련

### Phase 1. PDF 파싱

**목표:** PDF의 내용을 기계가 처리할 수 있는 형태로 변환한다.

- [ ] PDF에서 텍스트 추출
- [ ] 제목, 문단, 표, 이미지 구분
- [ ] 페이지 번호와 원본 위치 보존
- [ ] 파싱 결과를 Markdown으로 저장
- [ ] 표와 그림이 제대로 추출되었는지 확인

**후보 도구:** PyMuPDF4LLM, Docling 등

### Phase 2. 교재 내용 구조화

**목표:** 교재 내용을 단순한 텍스트가 아니라 개념 단위로 관리한다.

- [ ] 개념별 정의와 설명 정리
- [ ] 개념 사이의 관계 기록
- [ ] 조건, 예외, 비교 대상 정리
- [ ] 표와 그림에서 필요한 정보 추출
- [ ] 출처 페이지 연결

개념 데이터 예시:

```json
{
  "id": "concept_001",
  "name": "개념 이름",
  "definition": "개념의 정의",
  "conditions": [],
  "related_concepts": [],
  "source_pages": []
}
```

초기에는 JSON 파일로 관리하고, 데이터가 많아지면 SQLite 등으로 옮긴다.

### Phase 3. 기출문제 분석

**목표:** 기출문제를 분석하여 어떤 개념을 어떤 방식으로 출제하는지 파악한다.

- [ ] 문제와 선지, 정답, 해설 분리
- [ ] 문제별 핵심 개념 연결
- [ ] 문제 유형 분류
- [ ] 조건 해석 및 자료 분석 등 출제 요소 기록
- [ ] 자주 등장하는 개념과 유형 확인

기출문제는 단순한 예시 데이터가 아니라, 문제 생성 시 참고할 출제 기준으로 활용한다.

### Phase 4. 문제 생성

**목표:** 교재 개념과 기출문제의 출제 방식을 참고해 새로운 문제를 만든다.

- [ ] 생성할 개념과 문제 유형 선택
- [ ] 관련 개념 및 출제 요소 검색
- [ ] 문제와 선지 생성
- [ ] 정답 및 해설 생성
- [ ] 출력 형식을 Pydantic 등으로 검증
- [ ] 생성 결과를 JSON으로 저장

초기에는 객관식 문제 하나를 생성하는 기능부터 구현한다. 이후 자료 해석형 문제, 복합 개념 문제 등으로 확장한다.

### Phase 5. 문제 검증

**목표:** 생성된 문제의 오류를 최대한 줄인다.

- [ ] 정답과 해설의 논리적 일관성 확인
- [ ] 선지별 정오 판단 근거 확인
- [ ] 교재 내용과 충돌하는지 확인
- [ ] 교육과정 범위를 벗어나는지 확인
- [ ] 기출문제와 지나치게 유사한지 확인
- [ ] 사람이 최종 검수하고 수정할 수 있는 인터페이스 마련

자동 검증만으로 정확성을 보장할 수 없으므로, 초기에는 사람의 검수를 필수 단계로 둔다.

### Phase 6. 문서 출력

**목표:** 생성된 문제를 실제로 풀 수 있는 시험지 형태로 만든다.

- [ ] 문제 번호와 선지 자동 배치
- [ ] 시험지와 정답·해설 분리
- [ ] 표와 그림 배치
- [ ] 페이지 나눔과 문서 서식 처리
- [ ] DOCX 또는 PDF 출력

초기 출력은 DOCX로 시작하고, 필요에 따라 PDF나 HWPX를 추가한다.

## 5. 기술 스택 후보

| 영역 | 후보 |
|---|---|
| 언어 | Python |
| 패키지 관리 | uv |
| PDF 파싱 | PyMuPDF4LLM, Docling |
| 데이터 검증 | Pydantic |
| 데이터 저장 | JSON → SQLite |
| AI 문제 생성 | LLM API |
| 문서 출력 | python-docx |
| 테스트 | pytest |

구현하면서 실제 데이터에 적합한 도구를 선택한다. 처음부터 모든 기술을 도입하지 않는다.

## 6. MVP 범위

첫 번째 목표는 **교재 일부를 입력하면 검수 가능한 객관식 문제 몇 개를 생성하고, 시험지 형태로 출력하는 것**이다.

MVP에 포함할 기능:

- [ ] PDF 한 개에서 텍스트 추출
- [ ] 소수의 개념을 구조화
- [ ] 관련 기출문제를 수동으로 연결
- [ ] 객관식 문제와 해설 생성
- [ ] 결과를 JSON으로 저장
- [ ] DOCX로 출력
- [ ] 생성된 문제를 직접 검수하고 평가

초기 버전에서는 자동 개념 그래프, 복잡한 RAG 시스템, 웹 서비스, 완전 자동 채점 등을 구현하지 않는다.

## 7. 품질 평가 기준

생성 문제의 수보다 품질을 우선한다.

- **정확성:** 정답과 해설이 올바른가?
- **교과 적합성:** 교재에서 다루는 개념과 범위에 부합하는가?
- **출제 타당성:** 문제의 조건과 선지가 명확한가?
- **유사도:** 기존 기출문제를 단순히 바꿔 쓴 수준은 아닌가?
- **해설 품질:** 정답의 근거와 오답의 이유가 설명되는가?
- **편집 품질:** 시험지로 출력했을 때 읽고 풀기 편한가?

평가 결과를 기록해 프롬프트와 생성 절차를 개선한다.

## 8. 향후 확장 아이디어

MVP가 충분히 작동한 뒤 검토한다.

- 개념 간 관계를 그래프로 관리
- 관련 개념과 기출문제를 자동 검색
- 문제 유형별 생성 템플릿 도입
- 표·그래프·상황 자료 자동 생성
- 문제 난이도 조절
- 여러 문제를 묶어 모의고사 구성
- 생성 문제의 품질 평가 자동화
- 웹 기반 문제 생성 및 검수 인터페이스
- 다른 직업탐구 과목으로 확장

## 9. 개발 원칙

1. **작동하는 최소 버전을 먼저 만든다.**
2. 파싱, 생성, 검증, 출력을 독립적인 모듈로 나눈다.
3. 생성 결과와 원본 자료의 출처를 추적할 수 있게 한다.
4. AI가 생성한 결과를 무조건 신뢰하지 않는다.
5. 복잡한 기술을 도입하기 전에 단순한 방법으로 해결 가능한지 확인한다.
6. 실제 사용자에게 필요한 기능인지 확인한 뒤 확장한다.
7. 외부 판매를 고려할 경우 교재·기출문제의 저작권과 이용 조건을 별도로 확인한다.

## 10. 첫 번째 실행 계획

수능 이후 다음 순서로 시작한다.

1. 교재 한 단원과 기출문제 일부를 선정한다.
2. PDF 파싱 결과를 직접 확인한다.
3. 개념 몇 개와 기출문제 몇 개를 수동으로 구조화한다.
4. 구조화한 자료를 활용해 문제를 생성한다.
5. 생성 문제의 정답과 해설을 직접 검수한다.
6. DOCX 시험지로 출력한다.
7. 결과가 쓸 만한지 평가한 뒤 다음 개발 단계를 결정한다.

**첫 번째 완료 기준:** 원본 자료의 출처를 확인할 수 있고, 사람이 검수할 수 있는 객관식 문제를 생성하여 문서로 출력하는 데 성공한다.
